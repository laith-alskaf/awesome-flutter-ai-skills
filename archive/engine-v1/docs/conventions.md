# AI Engineering OS — Formatting & Conventions

To ensure consistency across the OS and its language modules, all skills, documentation, and agent outputs must adhere to these conventions.

## 1. File & Directory Naming
- **Directories**: Always `kebab-case` (e.g., `cross-cutting`, `specialists`).
- **Files**: Always `kebab-case` (e.g., `policy-engine.md`, `ui-engineer.md`).
- **YAML Files**: Used exclusively for machine-readable configurations (`framework.yaml`, `capability-graph.yaml`).

## 2. Markdown Structure
All markdown documents generated by the OS or read by agents must use the following hierarchy:
- `#` (H1) for Document Titles.
- `##` (H2) for Major Sections.
- `###` (H3) for Subsections.
- Bullet points (`-`) for lists. Do not use asterisks (`*`).

## 3. Decision Trees
When representing a decision flow in markdown, use the vertical arrow `↓` to denote steps:

```text
Condition
↓
Yes
↓
Action
```

## 4. Confidence Formatting
Confidence must be represented via the 5-Star system in YAML blocks:

```yaml
confidence:
  rating: ★★★★☆
  basis: [Widget Tests, Runtime Logs]
  missing: [Production Telemetry]
```

## 5. Contract Definitions
When describing inputs and outputs for a component, use the `Contract:` prefix:

**Contract: Planner Output**
```json
{
  "tasks": ["UI", "API"]
}
```

## 6. YAML Capability Definition
Skill capabilities must be defined in standard YAML array format:

```yaml
skill: flutter-api-expert
depends_on:
  - flutter-clean-architecture
provides:
  - NetworkLayer
```

## 7. Tone and Communication
- Agents must communicate in a professional, concise, and direct manner.
- Avoid conversational filler ("I think", "Maybe").
- Use declarative statements ("The evidence indicates", "The root cause is").
