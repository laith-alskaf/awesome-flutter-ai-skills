# AI Engineering OS — Core Principles

The AI Engineering OS relies on these fundamental engineering principles. All components, skills, and agents must strictly adhere to them.

## 1. Evidence Over Assumption
Never recommend a solution based on intuition or generic best practices alone. Every recommendation must trace back to categorized evidence (Crash Logs, DevTools Profiles, Tests, User Requirements).
**Rule:** If evidence is missing, the agent MUST ask for it before proposing a fix.

## 2. Single Responsibility
Every skill, module, and OS component has a strictly defined boundary.
**Rule:** Do not attempt to solve problems outside your `Capability Graph` registration. Delegate instead.

## 3. Contract-First Architecture
Communication between OS components (Planner → Scheduler → Orchestrator → Specialist → Validator) is strictly governed by `Input → Output` contracts.
**Rule:** Never break a contract. Outputs must always match the expected structural definition.

## 4. Fail Fast
Detect architectural conflicts and anti-patterns as early as possible (e.g., in the Planner or Validator phase).
**Rule:** Do not proceed with code generation if the underlying architecture is flawed or conflicting policies are detected.

## 5. Measure Before Optimize
Performance and size optimizations are strictly banned unless a measured bottleneck (Profile, Benchmark, Log) is provided.
**Rule:** Premature optimization is the root of all evil.

## 6. Incremental Change
Never propose massive, big-bang rewrites unless explicitly mandated by a `Migration Workflow`.
**Rule:** Prefer small, verifiable, and testable changes that preserve backward compatibility.

## 7. Security by Default
Tokens, passwords, and sensitive API configurations must always be handled securely (e.g., SecureStorage, Environment Variables).
**Rule:** Any violation of security policies must trigger an immediate halt and user escalation.

## 8. Composition Over Inheritance
UI and architecture components should be built through composition to maintain flexibility.
**Rule:** Avoid deep inheritance trees in UI frameworks.

## 9. Testability First
Code generated by the OS must be testable.
**Rule:** Always decouple business logic from UI frameworks and third-party dependencies to ensure unit testability.

## 10. Traceability (ADR)
Every major architectural decision must be recorded and justified.
**Rule:** Create an Architecture Decision Record (ADR) for any choice that impacts scalability, security, or maintainability.
